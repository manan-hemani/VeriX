# VeriX — AI-Powered Claim Verification & Evidence Tracing

**Investigate claims. Trace evidence. Understand the truth.**

VeriX is an AI-powered claim verification platform that investigates online claims using live web search, iterative evidence gathering, and AI-driven analysis. Instead of simply returning a verdict, it aims to show users the evidence behind an assessment, highlight contradictions, identify information gaps, and visualize relationships between claims and their sources.

Built for the **SerpApi India Hackathon 2026**, VeriX combines live search data with AI reasoning to make online claim investigation more transparent, explainable, and accessible.

---

## Problem Statement

The rapid spread of misinformation and misleading claims across digital platforms makes it difficult for users to distinguish reliable information from unsupported or contradictory statements. Traditional fact-checking often requires time-consuming manual research across multiple sources and may not clearly explain how a conclusion was reached.

VeriX addresses this challenge by automating evidence gathering and analysis, presenting traceable sources, identifying conflicting information, and communicating uncertainty instead of relying solely on a binary true-or-false verdict.

## Our Solution

VeriX transforms claim verification into an interactive investigation process. When a user submits a claim, the backend breaks it into smaller research questions, retrieves relevant information using SerpApi, and analyzes the collected evidence with large language models.

If the evidence is insufficient, the investigation can continue with additional searches. Once the research is complete, the platform presents an assessment, confidence information, evidence summaries, source references, contradictions, and an interactive evidence graph.

Our goal is to promote **non-biased AI-assisted fact-checking** by considering supporting and opposing evidence, acknowledging uncertainty, and making the investigation process visible to users.

## Key Features

### 1. AI-Powered Claim Investigation

- Accepts natural-language claims from users.
- Breaks complex claims into smaller, searchable subclaims.
- Uses iterative research and evidence analysis.

- Uncertain or inconclusive evidence

- Supports additional searches when further research is required.

## SerpApi Integration

SerpApi is a core component of VeriX's live research pipeline. The backend sends search queries related to the original claim and its subclaims to SerpApi and receives structured search results.

The application uses the returned information, including available titles, links, snippets, and source metadata, as input for subsequent AI analysis. The AI evaluates the relevance of the results, looks for evidence supporting or contradicting the claim, and identifies areas that require further research.

SerpApi supplies search data; it does not independently determine whether a claim is true or false. The final assessment is generated by the investigation pipeline using the evidence gathered from search results.

**SerpApi's role:** Live information retrieval.

**AI's role:** Claim decomposition, evidence analysis, contradiction detection, and assessment generation.

**VeriX's role:** Orchestrating the investigation and presenting the results in an understandable, traceable format.

## System Architecture

VeriX follows a frontend-backend architecture.

**Frontend**

- Collects user-submitted claims.
- Initiates investigations through the backend API.
- Receives live events through SSE.
- Displays investigation progress, summaries, and evidence visualizations.

**Backend**

- Validates incoming claims.
- Coordinates the investigation workflow.
- Generates subclaims and search queries.
- Retrieves results through SerpApi.
- Invokes the configured AI service to analyze evidence.
- Repeats research when necessary.
- Builds the final assessment and evidence graph data.
- Persists completed investigations in MongoDB.

**AI and Search Services**

- SerpApi provides live search results.
- Gemini performs AI analysis when configured.
- Groq provides an alternative inference provider when the fallback is configured.
- The investigation service coordinates these components.

**Database**

- MongoDB stores investigation results for subsequent retrieval.

## Getting Started

### Prerequisites

Install or obtain the following:

- Node.js and npm
- MongoDB, either locally or through MongoDB Atlas
- A SerpApi API key
- A Gemini API key
- Groq API credentials if using the fallback provider

### 1. Clone the Repository

```bash
git clone https://github.com/manan-hemani/VeriX
cd VeriX
```

### 2. Install Dependencies

```bash
cd backend
npm install
```

Then:

```bash
cd ../frontend
npm install
```


### 3. Configure the Backend Environment

Create a `.env` file in the backend directory:

```env
PORT=3000
MONGODB_URI=your_mongodb_connection_string
SERPAPI_KEY=your_serpapi_api_key
GEMINI_API_KEY=your_gemini_api_key
GROQ_API_KEY=your_groq_api_key
```

Use only the AI-provider variables required by your current implementation. If your AI service uses different environment variable names, retain those names.

### 4. Configure the Frontend Environment

Create a `.env` file in the frontend directory:

```env
VITE_BACKEND_URL=http://localhost:3000/api
```

This value assumes the Express API is mounted under `/api` and the backend runs on port `3000`.

### 5. Start the Backend

```bash
cd backend
npm run dev
```

If your backend does not define a `dev` script, use the start command configured in its `package.json`.

### 6. Start the Frontend

In a separate terminal:

```bash
cd frontend
npm run dev
```

Open the local URL printed by Vite in your terminal.

> **Note:** The directory names and npm scripts above are conventional examples. Match them to your repository's actual structure and `package.json` files.

## API Endpoints

The following endpoints reflect the investigation API structure used by VeriX. The exact response shapes and HTTP status codes depend on the controller implementation.

| Method | Endpoint                                 | Purpose                               |
| ------ | ---------------------------------------- | ------------------------------------- |
| `POST` | `/api/investigations`                    | Create an investigation               |
| `GET`  | `/api/investigations`                    | Retrieve investigations               |
| `GET`  | `/api/investigations/:id`                | Retrieve a saved investigation        |
| `POST` | `/api/investigations/live`               | Start a live investigation            |
| `GET`  | `/api/investigations/live/:runId/events` | Receive investigation events over SSE |

### Start a Live Investigation

Example request:

```http
POST /api/investigations/live
Content-Type: application/json
```

```json
{
  "claim": "Drinking coffee before exercise improves athletic performance"
}
```

The live endpoint returns a run identifier used to establish the event stream.

### Subscribe to Investigation Events

```http
GET /api/investigations/live/<runId>/events
Accept: text/event-stream
```

The frontend listens for events such as claim receipt, search progress, evidence analysis, and completion, depending on which events the backend emits.

### Retrieve Saved Results

The completed investigation exposes an `investigationId` used to retrieve its saved result.

For example:

```text
investigationId: 9913-CWA
```

This identifier is distinct from the temporary `runId` used for live event streaming.

## Responsible AI and Limitations

VeriX is designed to support evidence-based research, not replace human judgment.

- Search results may be incomplete, outdated, or misleading.
- A source appearing in search results does not automatically make it reliable.
- AI-generated assessments may contain errors or overlook relevant context.
- Confidence scores are estimates produced by the application, not statistical proof of correctness.
- Conflicting evidence should be presented and interpreted in context.
- The system should communicate uncertainty when available evidence is insufficient.

VeriX aims to support non-biased AI-assisted analysis by evaluating relevant evidence from multiple perspectives. However, it cannot guarantee complete neutrality or eliminate bias.

Users should consult original sources before making important decisions based on an investigation.
